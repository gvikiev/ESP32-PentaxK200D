# Архитектура и спецификация системы дистанционного управления Pentax K200D на базе ESP32-S3

## 1. Архитектурный обзор и ключевые особенности системы

### Ключевые архитектурные решения:

* **Двойственность USB-режимов меню K200D:**
  * **Режим [PC] (USB Mass Storage Class `0x08` / BOT):** Основной режим работы. Использует проприетарный протокол **Pentax Vendor SCSI** (SCSI OpCode `0xF0`). Обеспечивает спуск затвора, фокусировку, считывание и изменение всех параметров, а также выгрузку отснятых кадров из RAM-буфера камеры.
  * **Режим [PictBridge] (Still Image Class `0x06` / PTP):** Опциональный режим. На K200D предназначен для прямой печати на принтер. При подключении к хосту использует PTP-операции (`GetObjectHandles`, `GetThumb`, `GetObject`) для чтения файлов с SD-карты.
* **Приоритет режима [PC] как единого универсального канала:** Камера Pentax K200D в режиме **[PC]** при подключении по USB одновременно регистрирует SCSI-накопитель. Реализация собственного низкоуровневого BOT-транспорта позволяет совмещать отправку вендорских команд `0xF0` с выполнением стандартных SCSI-команд чтения `READ(10)`. Это дает возможность просматривать SD-карту как файловую систему FAT (через библиотеку FatFs в режиме Read-Only) **без переключения меню камеры в PictBridge**.
* **Аппаратные рамки ESP32-S3:**
  * Встроенный USB PHY поддерживается в режиме **Full-Speed (12 Мбит/с)**. Реальная пропускная способность передачи данных составляет **0.6–1.0 МБ/с**.
  * Кадры JPEG (10 Мп) выгружаются за 2–4 секунды, несжатые RAW (PEF/DNG) размером 10–14 МБ — за 12–18 секунд.
  * В связи с отсутствием аппаратных таймаутов передач в ESP-IDF USB Host, в прошивку встраивается программный Watchdog для принудительной сбросовой последовательности (BOT Reset Recovery).
* **Жизненный цикл tether-снимков:**
  * Кадры, снятые через удаленное управление по USB, **не записываются на SD-карту камеры**, а сохраняются во внутреннем RAM-буфере процессора Pentax (до 10 слотов).
  * Выгрузка кадра происходит по цепочке: *Опрос готовности -> Запрос сегментов (`0x04`) -> Потоковое скачивание блоками (`0x06`) -> Передача веб-клиенту -> Получение ACK от Web UI -> Удаление буфера в камере (`[02 03]`)*. Кадр не удаляется из памяти камеры до тех пор, пока браузер пользователя не подтвердит целостность приёма.

## 2. Протокол Pentax Vendor SCSI (Режим [PC])

### 2.1. Формат низкоуровневого пакета CDB

Все вендорские команды Pentax оборачиваются в стандартный пакет USB Mass Storage BOT CBW (Command Block Wrapper) с длиной блока команд 8 байт:

```
CDB = [ F0  TT  X2  X3  X4  X5  00  00 ]  (8 байт)
         │   └── Тип команды (0x4F, 0x24, 0x26, 0x49)
         └────── Vendor OpCode (всегда 0xF0)
```

| Тип `TT` | Наименование | Структура CDB | Направление данных |
| :--- | :--- | :--- | :--- |
| `0x4F` | **Send Arguments** | `[F0 4F off_lo off_hi len_lo len_hi 00 00]` | OUT (Передача аргументов в камеру) |
| `0x24` | **Send Command** | `[F0 24 group cmd_code len_lo len_hi 00 00]` | Нет данных (Выполнение операции) |
| `0x26` | **Get Command Status**| `[F0 26 00 00 00 00 00 00]` | IN (Опрос статуса выполнения, 8 байт) |
| `0x49` | **Read Result** | `[F0 49 off_lo off_hi len_lo len_hi 00 00]` | IN (Считывание результата команды) |

* **Порядок байт (Endianness):** Для модели Pentax K200D аргументы передаются и разбираются исключительно в формате **Big-Endian**.
* **Цикл выполнения высокуровневой команды:**
  1. Если у команды есть аргументы, они кодируются по 32 бита BE и отправляются через `0x4F` (offset выравнивается по 4 байтам).
  2. Выполняется команда `0x24` с указанием группы, кода операции и длины аргументов.
  3. Запускается цикл опроса состояния `0x26` с интервалом **50 мс**. Байт состояния `S1`: `0x01` — успех, `0x81` — команда недоступна, `0x82` — отклонена, `0x83` — неверный параметр.
  4. При наличии ответа выполняются запросы `0x49` для считывания байт результата.

## 3. Смешанный BOT/SCSI слой и файловая система SD-карты

Официальный компонент ESP-IDF `usb_host_msc` спроектирован строго под флеш-накопители и отклоняет неофициальные SCSI CDB. В данном проекте используется **собственный unified-драйвер USB Mass Storage BOT**, реализующий обслуживание двух каналов:

```
                            ┌─────────────────────────────────┐
                            │  Unified BOT Transport Engine   │
                            └────────────────┬────────────────┘
                                             │
                      ┌──────────────────────┴──────────────────────┐
                      ▼                                             ▼
       [ Channel A: Pentax Vendor SCSI ]             [ Channel B: Standard SCSI Disk ]
       Command OpCode: 0xF0                          Command OpCodes: 0x12, 0x25, 0x28
       ├─ Status & Control Commands                  ├─ SCSI INQUIRY
       ├─ Shooting Trigger                           ├─ READ CAPACITY(10)
       └─ RAM Buffer Streaming Pipeline              └─ READ(10) Block Storage Access
                                                                    │
                                                                    ▼
                                                     ┌──────────────────────────────┐
                                                     │ FatFs VFS Engine (Read-Only) │
                                                     │ └─ SD Card Gallery Access    │
                                                     └──────────────────────────────┘
```

1. **Мультиплексирование обмена:** Драйвер поддерживает thread-safe очередь транзакций. Запросы Web UI к SD-карте (`READ(10)`) паузируются во время выполнения операций съёмки и выгрузки кадров из RAM-буфера.
2. **FatFs VFS (Read-Only):** Файловая система SD-карты монтируется в режиме "Только чтение". Это защищает файловую систему FAT16/FAT32 камеры от повреждения при совпадении фоновых операций камеры и микроконтроллера.

## 4. Драйвер режима [PictBridge] (PTP Engine)

При переключении режима USB в меню камеры на **[PictBridge]** (`bInterfaceClass = 0x06`), прошивка переводит USB-стек в PTP-режим:

```c
typedef struct __attribute__((packed)) {
    uint32_t length;      // Длина контейнера (включая заголовок)
    uint16_t type;        // 1: Command, 2: Data, 3: Response, 4: Event
    uint16_t code;        // Код операции (OperationCode)
    uint32_t trans_id;    // Идентификатор транзакции
    uint32_t params[5];   // Параметры PTP
} ptp_container_t;
```

* **Реализованный набор операций PTP:** `OpenSession` (`0x1002`), `CloseSession` (`0x1003`), `GetDeviceInfo` (`0x1001`), `GetStorageIDs` (`0x1004`), `GetObjectHandles` (`0x1007`), `GetObjectInfo` (`0x1008`), `GetThumb` (`0x100A`), `GetObject` (`0x1009`).
* **Динамическое выявление возможностей (Capabilities Discovery):** После открытии сессии драйвер запрашивает `GetDeviceInfo`. Если в массиве `OperationsSupported` отсутствуют коды съёмки, прошивка автоматически помечает в Web UI функционал съёмки как `unavailable` и выводит пользователю информационный баннер со строгой инструкцией по переключению меню в [PC].

### 5.2. Реализация низкоуровневых компонентов (ESP-IDF 5.x C++)

#### 1. Структура низкоуровневого BOT пакета:

```c
#include <stdint.h>
#include <string.h>
#include "esp_err.h"

#define BOT_CBW_SIGNATURE 0x43425355u
#define BOT_CSW_SIGNATURE 0x53425355u

typedef struct __attribute__((packed)) {
    uint32_t dCBWSignature;          // "USBC"
    uint32_t dCBWTag;                // ID транзакции
    uint32_t dCBWDataTransferLength; // Длина передаваемых данных
    uint8_t  bmCBWFlags;             // 0x80: IN (Read), 0x00: OUT (Write)
    uint8_t  bCBWLUN;               // 0
    uint8_t  bCBWCBLength;          // Длина SCSI CDB = 8 байт
    uint8_t  CBWCB[16];              // SCSI Command Block
} bot_cbw_t;

typedef struct __attribute__((packed)) {
    uint32_t dCSWSignature;          // "USBS"
    uint32_t dCSWTag;
    uint32_t dCSWDataResidue;
    uint8_t  bCSWStatus;             // 0: Success, 1: Command Failed, 2: Phase Error
} bot_csw_t;

// Вспомогательные функции кодирования Big-Endian
static inline void put_be32(uint8_t *p, uint32_t val) {
    p[0] = (uint8_t)(val >> 24);
    p[1] = (uint8_t)(val >> 16);
    p[2] = (uint8_t)(val >> 8);
    p[3] = (uint8_t)(val);
}

static inline uint32_t get_be32(const uint8_t *p) {
    return ((uint32_t)p[0] << 24) | ((uint32_t)p[1] << 16) | ((uint32_t)p[2] << 8) | ((uint32_t)p[3]);
}
```

#### 2. Формирование команд Pentax CDB:

```c
void build_pentax_cdb_cmd(uint8_t *cdb, uint8_t group, uint8_t cmd_code, uint16_t args_len) {
    memset(cdb, 0, 8);
    cdb[0] = 0xF0;       // OpCode Pentax Vendor SCSI
    cdb[1] = 0x24;       // Command Exec
    cdb[2] = group;      // Группа команд
    cdb[3] = cmd_code;   // Код команды
    cdb[4] = (uint8_t)(args_len & 0xFF);
    cdb[5] = (uint8_t)((args_len >> 8) & 0xFF);
}

void build_pentax_cdb_status(uint8_t *cdb) {
    memset(cdb, 0, 8);
    cdb[0] = 0xF0;
    cdb[1] = 0x26;       // Poll Status
}
```

#### 3. Разбор 408-байтового статуса Pentax K200D:

```c
typedef struct {
    uint16_t bufmask;
    uint32_t set_shutter_nom, set_shutter_denom;
    uint32_t set_aperture_nom, set_aperture_denom;
    int32_t  ev_comp_nom, ev_comp_denom;
    uint32_t iso;
    uint32_t image_format;      // 0: JPEG, 1: RAW, 2: RAW+JPEG
    uint32_t jpeg_res_idx;      // 0: 10M, 1: 6M, 2: 2M
    uint32_t jpeg_quality;      // Звёзды (3 - hw_val)
    uint32_t raw_format;        // 0: PEF, 1: DNG
    uint32_t custom_image_tone; // 0..5
    uint32_t exposure_mode;
    uint32_t af_mode;
    uint32_t shake_reduction;
    uint32_t lens_min_f_nom, lens_min_f_denom; // Светосила
    uint32_t focal_length_nom, focal_length_denom; // Zoom
} k200d_status_t;

esp_err_t parse_k200d_status(const uint8_t *buf, size_t len, k200d_status_t *st) {
    if (len < 408) return ESP_ERR_INVALID_SIZE;

    st->bufmask             = ((uint16_t)buf[0x16] << 8) | buf[0x17];
    st->set_shutter_nom     = get_be32(&buf[0x2C]);
    st->set_shutter_denom   = get_be32(&buf[0x30]);
    st->set_aperture_nom    = get_be32(&buf[0x34]);
    st->set_aperture_denom  = get_be32(&buf[0x38]);
    st->ev_comp_nom         = (int32_t)get_be32(&buf[0x3C]);
    st->ev_comp_denom       = (int32_t)get_be32(&buf[0x40]);
    st->iso                 = get_be32(&buf[0x60]);
    st->image_format        = get_be32(&buf[0x78]);
    st->jpeg_res_idx        = get_be32(&buf[0x7C]);
    st->jpeg_quality        = 3 - get_be32(&buf[0x80]);
    st->raw_format          = get_be32(&buf[0x84]);
    st->custom_image_tone   = get_be32(&buf[0x88]);
    st->exposure_mode       = get_be32(&buf[0xAC]);
    st->af_mode             = get_be32(&buf[0xB8]);
    st->shake_reduction     = get_be32(&buf[0xDA]);
    st->lens_min_f_nom      = get_be32(&buf[0x13C]);
    st->lens_min_f_denom    = get_be32(&buf[0x140]);
    st->focal_length_nom    = get_be32(&buf[0x17C]);
    st->focal_length_denom  = get_be32(&buf[0x180]);

    return ESP_OK;
}
```

### Главные модули интерфейса Web UI:

1. **Индикатор связи и режима (Header Banner):** Отображает текущий режим камеры. Если пользователь открыл вкладку «Съемка», а камера находится в режиме `[PictBridge]`, панель управления скрывается, а на экран выводится шаговая инструкция: *«Перейдите в меню камеры: MENU -> Set-up -> USB Connection -> выберите [PC]»*.
2. **Панель параметров экспозиции:** Выпадающие списки и интерактивные кнопки быстрого переключения выдержки (от 1/4000s до 30s), диафрагмы (динамически от ограничения светосилы объектива до F22/F32), ISO (100–1600), EV (+/- 3.0 EV).
3. **Панель спуска и фокусировки:**
   * Кнопка **«AF (Focus Lock)»** (команда `[10 05](1)`).
   * Большая кнопка **«Спуск (Release)»** (команда `[10 05](2)`). Автоматически блокируется, если маска `bufmask` показывает заполненость всех 10 слотов RAM-буфера.
   * Кнопка **«Зеленая кнопка (Green Button)»** (команда `[10 07]`) для мгновенного сброса экспозиции в идеальное значение по программе P.
   * Режим **«Bulb-таймер»** (команда `[10 0D]`): позволяет задавать произвольную длинную выдержку (например, 45 секунд или 3 минуты) с автоматическим отсчетом времени микроконтроллером.
4. **Программный интервалометр:** Реализуется на стороне ESP32-S3. Пользователь задает количество кадров и паузу между ними. ESP32 отрабатывает цикл съёмки, ожидает заполнения буфера и выгружает кадры в фоновом режиме.
5. **Галерея SD-карты и буфера:** Окно предварительного просмотра снимков. Показывает активные кадры в RAM-буфере камеры, позволяет просматривать превью кадра через 2 секунды после снимка и скачивать исходные PEF/DNG/JPEG файлы.

### Фаза 0. Исследования на ПК (Снятие гипотез H-1…H-18)
* **Цель:** Изучение физической камеры Pentax K200D с помощью утилит `pktriggercord-cli`, `lsusb`, `Wireshark`/`usbmon`.
* **Задачи:**
  1. Подтвердить гипотезу H-1 (доступность SD-карты по SCSI `READ(10)` в режиме [PC]).
  2. Снять дампы `[00 08]` статуса (408 байт) при ручном изменении нераззобранных параметров (WB, AE Metering, Flash mode, Color Space) для поиска их HEX-смещений (H-7).
  3. Измерить реальное время записи кадров CCD-матрицей в буфер при разных выдержках и проверить размеры буферов типа 8 (PREVIEW) и 9 (THUMBNAIL) (H-11, H-18).
  4. Зафиксировать точный PID устройства в режимах [PC] и [PictBridge].

### Фаза 1. Программный USB Host и классификация устройств на ESP32-S3
* **Задачи:**
  1. Настройка проекта в ESP-IDF 5.x, инициализация `usb_host_install`, создание daemon-задачи.
  2. Разработка схемы управления питанием VBUS шины USB через GPIO и транзисторный ключ.
  3. Парсинг дескрипторов интерфейса при подключении камеры и определение класса (`0x08` MSC vs `0x06` Still Image).
  4. Реализация механизма переподключения при отключении/включении камеры.

### Фаза 2. Собственный BOT-транспорт и базовые SCSI-команды
* **Задачи:**
  1. Реализация структуры CBW/CSW пакетов и обработчика bulk-IN / bulk-OUT конечных точек.
  2. Создание менеджера передач с разбивкой данных на блоки $\le 8128$ байт.
  3. Написание программного Watchdog-таймера для выполнения BOT Reset Recovery при зависаниях.
  4. Проверка стандартных SCSI команд: `INQUIRY`, `TEST UNIT READY`, `READ CAPACITY(10)`.

### Фаза 3. Протокол Pentax SCSI и разбор статуса K200D
* **Задачи:**
  1. Реализация функций формирования Pentax CDB пакетов `[F0 TT ...]`.
  2. Написание процедуры инициализации подключения (`Set Connect Mode [00 00]` -> `Get Identity [00 04]`).
  3. Реализация опроса статуса `[00 08]` (408 байт) и функции `parse_k200d_status()`.
  4. Создание механизма обработки порядка байт Big-Endian.

### Фаза 4. Менеджер параметров съёмки
* **Задачи:**
  1. Реализация функций записи параметров группы `[18 xx]` с обрамлением командами `DSPTaskWUReq [00 09]`.
  2. Создание слоя валидации передаваемых значений (проверка выдержки $\le 1/4000$, диафрагмы в границах светосилы объектива, ISO 100–1600).
